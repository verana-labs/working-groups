# Specification WG (SPEC-WG) — 2026-10-13

## Agenda

1. Documentation pull request and build/navigation rework
2. New implementation/demos working group, certification programme
3. Testnet v4 migration: wipe, playground use cases, cluster split and DNS mapping
4. Onboarding flows and known VS Agent / timing issues
5. Specification work: v5 writing approach and spec publication tooling
6. Team updates: Credo, post-quantum work, contributor status

## Discussion

**Documentation pull request.** Fabrice Rochette said he had reviewed the PR: the "Understand" section was well written, but the "Build" part would need rework because it is hard to find the right information in it. He intended to redo it only after the testnet migration to v4, and to add step-by-step screenshots (ecosystem creation, creating a corporation, joining an ecosystem) generated through an existing pipeline. He asked Ariel Gentile to approve the PR before the migration. Fabrice had used the documentation for local tests; the VS Agent appeared to work on version 0.9.1, though he lacked the ecosystem mnemonic to test his request. Ariel mentioned an upcoming 2.0.0 release.

**New working group, certification.** Fabrice announced a new working group launching Thursday at 8, with Bernard (French) and other folks. Its scope: demos and how to build them (playground-style), training workshops and certification. A certification programme is being prepared and partly published in a repository, with a free tier and a paid tier; a temporary link exists on the Verana Foundation site. The aim is to certify companies whose technical teams can implement Verana services. Fabrice wants testnet on v4 first so documentation and certification align. He also asked Bernard to look at deployment on AWS and Google Cloud, with everything to be verified against the documentation.

**Testnet migration and clusters.** Ariel reported devnet had been restarted and tested; Maxime validated the use cases, personal wallet worked, and Hologram is ready for publication pending an Android production test. Andrés would run the testnet migration. A full wipe of testnet is required for v4, and playground elements will be recreated — the four basic web use cases (Vesta, BH, Verandia/Crypto Exchange, personal wallet), estimated at about three to four hours. Fabrice asked that the wipe be announced on Discord announcements. On clusters: `*.playground.testnet.network` stays on the current cluster; everything else (indexer, graph, app, search, visualiser, faucet, explorer, SS ecosystem, org issuer, API/RPC proxy) moves to the new cluster, which will be testnet-only. Ariel had understood it the other way round but accepted. They mapped DNS entries live; Ariel would ask Andrés to confirm which services are actually used, noting many leftover test entries. Fabrice also asked that mnemonics created for testnet corporations be kept secret, and reminded that credentials should not be sent over Discord as it is not encrypted. Resource sizing was discussed: graph ~90–100 MB, indexer around 1 GB, VS Agent running on 256 MB.

**Onboarding flows.** Ariel confirmed onboarding is implemented, with a connection between the frontend and the associated VS Agent to track onboarding states and external OOB links. He warned of known issues: duplicate connections in VS Agent (being fixed by Tarun in v2), and timing problems where the trigger resolver fires before the final state is available, requiring retries. Both agreed the ordering of indexer notifications to agents needs to be made robust.

**Specifications.** Nothing had been decided on how to write the v5 specs. Ariel described using an IEEE/ISO-style template ("ASD 100" in transcript) on a side project, with a high-level requirements spec plus a more detailed design spec, and proposed trying it for v5. Fabrice shared a link to "spec-up T" from Trust over IP, similar to Docusaurus in appearance and navigable, and asked whether Docusaurus (already versioned v3, v4) could host a spec tab instead. Both agreed the current GitHub files are not navigable or human-readable enough.

**Other updates.** Ariel reported Credo progress with Robert's involvement, Tarun's pull requests fixing KMS bugs, Maxim's OpenID4VC fixes, and Martin's post-quantum work: the plan is an experimental Credo integration using the Noble pure-JavaScript library (Node and React Native) rather than native Askar support, since ML-DSA in RustCrypto is experimental. Fabrice suggested inviting Martin to the Implementation working group. Tarun's availability after his new job is still unconfirmed.

## Decisions

- The current cluster keeps `*.playground.testnet.network`; all other testnet services move to the new, testnet-only cluster.
- Testnet will be wiped and migrated to v4 today, with the four basic playground use cases redeployed and an announcement posted on Discord.
- Post-quantum support in Credo will start as an experimental integration using the Noble JavaScript library rather than native Askar support.
