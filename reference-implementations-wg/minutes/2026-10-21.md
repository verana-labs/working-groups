# Reference Implementation WG — 2026-10-21

## Agenda

1. V4 deployment on testnet
2. Infrastructure: cluster separation, playground resource footprint, VS Agent multi-tenancy
3. VS-Agent / Credo DIDComm v2 state, Hologram and verana-demos
4. Credo contributions and credential response encryption
5. Frontend spec-compliance gaps
6. Deployment practice (devnet vs testnet) and possible automation
7. Namespace-scoped kubeconfigs for external demo repos
8. Indexer/VPR migration PR and upgrade plan
9. Mediator and wallet websocket / message pickup stability
10. Stuck DIDComm PRs in the Open Wallet Foundation repo
11. Old demo DNS alerts
12. Post-quantum verifiable credentials

## Discussion

**V4 and V5.** Ariel Gentile reported that the V4 deployment on testnet was finally successful after the previous week's issues, with some polishing still needed in VS Agent before an official 2.0. Work on V5 has started following PRs on the specs and comments from Fabrice. Ariel wanted to review the items deliberately left out of the V5 specs because of their complexity, as well as the PRs moved to draft, but proposed doing this next week when Fabrice can attend.

**Infrastructure.** The clusters used for devnet and testnet have been separated so that core components (indexer, graph) run in a more stable environment. Ariel showed that the playground runs roughly 30 VS Agent instances (around 200 MB each), which is costly for mostly idle services; supporting multi-tenancy in VS Agent so several services can share one instance was named as immediate implementation work for the coming weeks. For now, resources were added to the test net cluster.

**VS Agent / Credo.** Many fixes landed in VS Agent and Credo for DIDComm v2. The store release of Hologram works with the playground over DIDComm v1; v2 support is being enabled in dev builds. After redeploying the playground, the duplicate-connection and race problems were described as almost gone. Ariel noted the verana-demos repo as a simpler example set (two issuers, two verifiers, chatbot and web flows) working with the latest VS Agent. He asked whether the new credential response encryption fix on the issuer side resolves the Swiss wallet incompatibility, or whether holder-side support is also needed; Maxime said holder-side support is needed. Ariel also noted the increased contribution activity in Credo from Tarun Vadde and Maxime.

**Frontend.** Andres Vallecilla said most of the gaps found against the V4 spec are now tracked as issues or have PRs; a final review may be needed but he believes coverage is largely complete.

**Deployment practice.** Ariel restated the rule: testnet uses stable versions, devnet tracks main. He suggested automating devnet upgrades (e.g. a daily job pulling dev versions) to avoid a PR per merge, noting the existing auto-approval for dev-net-only changes. Putting deployment back into source repos was rejected earlier to avoid sharing credentials, but could be reconsidered with scoped Kubernetes credentials. Andres offered to look at improving this.

**Namespace-scoped kubeconfigs.** Scoped kubeconfigs will be issued per external demo repo so they can deploy to the dev cluster with limits, instead of handing out full cluster access. The first case is Bernard's demo.

**Migration.** Pratik Kumar explained one PR adds a new store for faster queries and therefore needs a migration; he will group the smaller fixes into a single version and merge the migration PR last, since the upgrade plan lives in it. Ariel noted this will be the first real migration exercise since the previous practice of wiping state.

**Mediator / wallet.** Tarun is working on mediator and wallet improvements, studying real-time messaging systems (Signal, "edge award") and an optional spec field "live delivery" not implemented in Credo. He described dead sockets being dropped every 3–6 seconds while React Native does not observe pongs and TCP keep-alive is off, and proposed periodic status requests over the live socket with reconnect-with-jitter. Ariel gave background on websocket state handling across Android/iOS, the 3-second heartbeat, and the message pickup v2/v4 delivery acknowledgement history, and agreed stability needs work.

**Other.** Two DIDComm exchange protocol PRs in the Open Wallet Foundation Credo repo are blocked until the npm package naming/CI is fixed after the repo move; Ariel will handle it. The DNS alerts Andres saw relate to old V3-based demos, which will be shut down and later rebuilt on V4 in the dev environment. Ariel introduced Martin, a student working on post-quantum verifiable credentials, adding ML-DSA support to Askar, with Credo integration and a possible demonstration by year end.

## Decisions

- V5 specification review (excluded items and draft PRs) is deferred to next week's meeting with Fabrice.
- Namespace-scoped kubeconfigs will replace full cluster kubeconfigs for external demo repos.
- The old V3-based demos will be shut down rather than fixed.
- The migration PR will be merged last, after the smaller indexer/VPR fixes, grouped into one version with an upgrade plan.
