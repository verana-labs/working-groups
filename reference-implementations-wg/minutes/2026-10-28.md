# Reference Implementation WG — 2026-10-28

## Agenda

1. Credo / DIDComm v2 status and upcoming release
2. AI-assisted end-to-end and performance testing
3. Mediator and VS Agent releases
4. VPR release and devnet/testnet migration
5. SD-JWT credential exchange over DIDComm
6. V5 specification walkthrough (VPR and Verifiable Trust specs)
7. Ledger get/list methods
8. Tarun Vadde's departure

## Discussion

**Credo and DIDComm v2.** Ariel Gentile reported many fixes in Credo, including memory leaks in Askar and AnonCreds, and additional OpenID4VC coverage. After Tarun Vadde's recent work, DIDComm v2 support was described as noticeably more stable from a user perspective when tested with Hologram and the mediator, though logs had not been inspected in detail. A release (referred to as "0.8"/the next release) was said to be close. Maxime Mansiet said his open pull request had received feedback from Robert and Teemo and should be closed the same day; he had also collected issues from the Swiss wallet team and passed them on for their next version.

**Testing.** Ariel described recent experience on a partner demo where AI tooling drove emulators for end-to-end testing, and proposed using the same approach to build a meaningful test suite rather than accumulating AI-suggested tests, plus log analysis for bottlenecks and memory usage. He noted long-standing difficulty in load-testing Hologram, and said the scope should cover Hologram, the mediator and VS Agent message queuing/retries. He expected Maxime to work on this in the coming month.

**Releases.** Ariel considered it safe to upgrade the production mediator (currently on 1.4.1) and said Hologram would stay on DIDComm v1 for now, since v2 was mainly a priority for VS Agent; migrating Hologram to a v2 mediator later would not require new wallets. A VS Agent release was also judged feasible, with remaining OpenID4VC items (e.g. token status list) non-breaking and deferrable to a 2.1.

**VPR migration.** With 0.10.7 released, Pratik Kumar said he would send Andres Vallecilla the steps for the software upgrade proposal, noting a previous Cosmovisor-based script that replaces the binary automatically. Andres planned to run the migration on devnet that day using the gov proposal, before testnet.

**SD-JWT over DIDComm.** Ariel noted Tarun was designing protocols for issuing and verifying SD-JWT credentials over DIDComm, to be proposed to the DIF and then implemented in Credo, distinguishing W3C SD-JWT from the digital-credentials SD-JWT type.

**V5 specification.** Fabrice presented a single pull request each on the VPR and Verifiable Trust specs. Motivation: a business registry scenario would produce a ~300 GB ledger state under V4, reducible to ~10 GB. Key changes: tokenomics model C (trust unit no longer a pricing unit; trust deposit decay; slashing repaid at initial value); network governance by corporations; a new verifiable service entity holding the identifier ("V", generalised beyond DIDs), to which corporations, ecosystems and accreditations attach, allowing DID rotation and transfer between corporations and removing the need for unnecessary participant entries; renaming participant entry to accreditation; deletion from ledger state of revoked or expired accreditations (retained in the indexer); a participation trust deposit separated from accreditation so open schemas need no entry but can still be slashed; an "excluded" flag for permanent exclusion; credential schema configuration (subject kind, presentation mode public/on-request/on-approval, single credential format per schema among W3C JSON-LD, SD-JWT and mDoc); credential anchoring modes so that no-digest and non-revocable digests are pass-through transactions indexed but not persisted in state; renaming create/update session to credential exchange; a single verifiable user agent reward derived from the presented user agent credential; presentation digests with a validity period for proving freshness; message type enumerations; and only three required indexes. Payments were limited to DIDComm-compatible exchanges for now. Fabrice asked for help defining a protocol letting a verifier learn which credentials a holder has without obtaining the information for free, and stressed that human conceptual review of the specs matters more than AI review, since development is spec-driven. He noted V5 may contain breaking changes but V6, targeted for mainnet next year, must not.

**Get/list methods.** Fabrice proposed removing get and list methods since the indexer exists. Pratik argued get-by-key should stay as a second line of verification against the indexer; Fabrice agreed, while keeping the removal of list methods, which require indexes and ledger space.

**Departure.** Ariel announced that Tarun is leaving for another company next week, thanked him for contributions across the components, and raised possible part-time or freelance continuation. Tarun said he would keep contributing, including the SD-JWT-over-DIDComm RFC.

## Decisions

- Get-by-key methods will be kept in the ledger API; list methods will be removed.
- Hologram stays on DIDComm v1 for now; DIDComm v2 remains the priority for VS Agent.
- The VPR migration will be run on devnet first, then on testnet.
- V5 review takes a few days, with implementation work expected to start around next week.
